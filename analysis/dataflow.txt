===========================================================

DATAFLOW FROM SOURCE TO SINK
=============================

File: ffmpeg-vul-core/analysis/dataflow.txt
Description: Traces untrusted h.264 input through vulnerable code path to OOB access

-----------

[1] Untrusted Input: H.264 Video File (bitstream)
    |
    +-- Location: Network stream, local file, or memory buffer
    +-- Format: H.264 NAL unit stream
    +-- User Controlled: YES
    +-- Validation: MISSING in vulnerable version


PARSING STAGE
=============

[2] parse_slices_vulnerable()
    |
    +-- Function: Slice extraction and buffer allocation
    +-- File: src/h264_parse.c
    +-- Input: uint8_t *bitstream (untrusted)
    |
    v


[3] extract_slice_count()
    |
    +-- Operation: Read 4 bytes from bitstream
    +-- Code:
        slice_count = (bitstream[0] << 24) |
                      (bitstream[1] << 16) |
                      (bitstream[2] << 8) |
                      (bitstream[3]);
    |
    +-- Result: 32-bit integer
    +-- Validation: NONE
    +-- Potential Value: 0x00000000 to 0xFFFFFFFF
    |
    v


VULNERABLE COMPUTATION
======================

[4] Buffer Size Calculation
    |
    +-- Operation: Multiply slice_count * ENTRY_SIZE
    +-- Code:
        uint32_t entry_size = 16;
        size_t buffer_size = slice_count * entry_size;
    |
    +-- Issue: Integer Overflow Possible
    |
    +-- Example with slice_count = 0x40000000:
    |       0x40000000 * 16
    |       = 0x400000000 (68GB on 64-bit)
    |       = 0x0 (on 32-bit due to modulo 2^32)
    |
    +-- Result: buffer_size = 0 or very small value
    |
    v


MEMORY ALLOCATION
=================

[5] av_malloc(buffer_size)
    |
    +-- Function: Memory allocation
    +-- Input: buffer_size (computed from untrusted input)
    +-- Vulnerable State:
    |       - Expected size: 68GB
    |       - Allocated size: 0 bytes (or small value due to overflow)
    |
    +-- Return: Pointer to undersized memory block
    |
    v


UNSAFE WRITE LOOP
=================

[6] Slice Data Write Loop
    |
    +-- Code:
        for (uint32_t i = 0; i < slice_count; i++) {
            SliceInfo *slice = &buffer[i];
            // Write slice data
            slice->id = ...;
            slice->pos = ...;
            slice->size = ...;
            slice->type = ...;
        }
    |
    +-- Issue: Array access without bounds checking
    +-- Loop Iterations: slice_count (from untrusted input)
    +-- Array Size: Undersized buffer (due to overflow in [4])
    |
    v


OUT-OF-BOUNDS ACCESS
====================

[7] buffer[i] Access
    |
    +-- Calculation: offset = i * sizeof(SliceInfo)
    +-- Expected: offset < buffer_size for all i < slice_count
    +-- Actual (vulnerable): offset >= buffer_size for i >= threshold
    |
    +-- Example with slice_count = 0x40000000, actual_alloc = 256MB:
    |       i = 0:          offset = 0x0       ✓ SAFE
    |       i = 1000:       offset = 0x4000    ✓ SAFE
    |       i = 16777216:   offset = 0x100000000 (256MB in bytes) ✗ OOB
    |       i = 33554432:   offset = 0x200000000 ✗ OOB
    |
    v


HEAP CORRUPTION
===============

[8] Memory Violation
    |
    +-- Type: Heap Buffer Overflow (CWE-787)
    +-- Location: buffer[i] where i >= buffer_capacity/entry_size
    +-- Effect:
    |       - Write to unallocated heap memory
    |       - Corrupt adjacent heap blocks
    |       - Corrupt heap metadata
    |       - Potential vtable/pointer corruption
    |
    v


EXPLOITATION SCENARIOS
======================

Scenario A: INFORMATION DISCLOSURE
    heap corruption [8] -> read corrupted metadata -> leak pointer -> ASLR bypass

Scenario B: DENIAL OF SERVICE
    heap corruption [8] -> corrupt allocator metadata -> crash in malloc/free -> DoS

Scenario C: CODE EXECUTION (Complex)
    heap corruption [8] -> corrupt function pointer -> call arbitrary function -> RCE


DETECTION POINTS
================

Static Analysis:
    1. [3] Unchecked read from bitstream
    2. [4] Integer multiplication without overflow check
    3. [6] Loop with user-controlled limit
    4. [7] Array access without bounds validation

Dynamic Analysis:
    1. [5] AddressSanitizer: heap-buffer-overflow detected
    2. [8] Memory write detected beyond allocation boundary

EXECUTION TRACE EXAMPLE
=======================

Input: h264_file with malicious slice_count = 0x40000000

[1] Load bitstream

    for (i = 0; i < 0x40000000; i++) {

[7] First iterations OK (within allocated memory)
        i = 0:   offset = 0x0         → buffer[0] ✓
        i = 1:   offset = 0x10        → buffer[1] ✓
        i = 256: offset = 0x1000      → buffer[256] ✓

[8] Later iterations OOB

        printf: "WARNING: Writing beyond buffer"

[8] FINAL: Heap corruption detected by ASan or system crash
